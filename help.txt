1) Docker Image
The app was designed to run on a Docker, using alpine image as base. you can use
mperon/backupfire:latest as image name to run. To configure, you need to set up:

  backupfire:
    build:
      context: .
    container_name: mperon/backupfire:latest
    # Mounts:
    # - ./data   -> backups output
    # - ./config -> config/key files (read-only)
    # - ./sources -> sources directories you want to backup files (you can have several folder in)
    volumes:
      - ./volumes/data:/app/data
      - ./volumes/config:/app/config:ro
      - ./var/www:/app/sources/www:ro
      - ./var/logs:/app/sources/logs:ro
    environment:
      BK_CONFIG=new.conf

Before going to each section of the config, lets see each Type and Action we have
enabled in the program.

A type of an task is how it will be run. Inside a task you have an action, that is what you want to do.
Each Type have their own Actions, that correlates with the type.

We have today three types of tasks:
a) Local: the Type local only run locally, doesnt upload files to remote. Usually you use it
to copy files locally. You dont need to specify an Action because there is only one: CopyFiles.
b) Remote: The type remote only upload files from a source to a destiny. You dont need to specify an Action because there is only one: CopyFiles.
c) Backup: This type is the most complex one we have today, becase have several actions but also backup
will run the action (copy files, database backup, log backup, etc..) in an working dir, compress it, then can encript and upload to a remote.
So, as complex it its, we gonna spend more time with it. Backup has three actions today:
c.1) Database | Db | Postgres: connect to a postgres database, and generate a full backup from it. The options will be
discussed in anoter section. (generate a backup from the database, compress, encrypt and upload, if configured)
c.2) CopyFiles | copy | files: copy files from From and compress, encrypt and upload (if configured).
c.3) DockerLogs | logs: generate a dump from logs in docker services currently running and compress, encrypt and upload (if configured).

We can add more Types and Actions in the future, if we see the need. The tool was designed to be extensible.

Limit the backup files. This is useful to automatically limit the number of files based in
the rules in the options Keep* that I will show below. If false, it will not limit files and
will not generate weekly, daily, montly and yearly copies. If set true, will copy the backup to have
one per day, week, month and year of the backup.

Before=checkSize %From% > 10mb
After=checkSize %To% > 8mb
Run before/after a action is performed. You can create a script
and check if network folder is mounted, or check number of files
size of dir, etc..
backupFire passes to script enviroment variables as From, To, etc..
besides, you can use all action options with %% as %To%, etc..
Backup has several internal programs useful:
  checkSize [folder] [operator] [size]
  Check the size of folder using operators: >, >=, <, <=, !=
  Example: Before=checkSize "%From%" > 10mb

  countFiles [folder] [operator] [size]
  Check count the files of folder using operators: >, >=, <, <=, !=
  Example: Before=countFiles "%From%" > 23.000

Is important to know that if Before is set, the action will only run if
the before script is sucessfull (returns 0). if not, stops the action!
All dependencies actions will not be executed!
If after is set, then the action will be executed, but all dependent actions
will not be called.
Or any apllication or script: Before=~/bin/doSomething.sh --dir=%From% --countWordFiles=33

You can have multiple config files in the conf directory and choose the one using
backupfire -c file, for example, backupfire -c new.conf. If you are using docker compose
you can set the variable BK_CONFIG= with the file. (show an example to the user)


The other important file in config folder is rclone.conf. This file need to have
a valid rclone config. If you want to upload files to remote, this file is mandatory
You can create locally in your machine by running rclone config and then copying The
file $HOME/.rclone.conf to the config/ folder. Also, you can run in the image, by running
docker run -it /bin/bash; and then run rclone config there. The program is smart enought
to find the .rclone.conf file there if not provided by you. You can set where rclone config is
by setting in [General] the config: RemoteConfigFile=path_to_file
A sample rclone.conf file:
[pcloud]
type = pcloud
hostname = api.pcloud.com
token = {"access_token":"...","token_type":"bearer","expiry":"0001-01-01T00:00:00Z"}
